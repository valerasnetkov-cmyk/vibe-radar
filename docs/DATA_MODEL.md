# Data Model — Vibe Radar

This document defines the conceptual model. Stage 01 may adapt column names while preserving semantics.

## Repository

Canonical GitHub project identity.

Suggested fields:

- `id` internal UUID/identity
- `provider` (`github` initially)
- `provider_repository_id`
- `owner`
- `name`
- `full_name`
- `html_url`
- `default_branch`
- `description`
- `primary_language`
- `license_spdx`
- `topics`
- `created_at_provider`
- `pushed_at_provider`
- `first_seen_at`
- `last_seen_at`
- `status`

Unique: `(provider, provider_repository_id)`.

## RepositorySnapshot

Time-series observation used for growth calculation.

Fields:

- `repository_id`
- `observed_at`
- `stars`
- `forks`
- `open_issues`
- `watchers` when provider semantics are useful
- `pushed_at_provider`
- selected activity metadata
- `source_event_id`

Do not overwrite historical snapshots.

## RepositoryRelease

Normalized release/tag signal.

Fields:

- `repository_id`
- `provider_release_id`
- `tag_name`
- `name`
- `published_at`
- `is_prerelease`
- `is_draft`
- bounded release summary/provenance

## SourceEvent

Provenance for discovery/refresh.

Fields:

- source/provider
- source query/topic/watchlist identifier
- observed timestamp
- normalized outcome
- error/status metadata without secrets

## Score

Explainable score record.

Fields:

- `repository_id`
- `score_version`
- `calculated_at`
- `growth_score`
- `relevance_score`
- `freshness_score`
- `activity_score`
- `community_score`
- `documentation_score`
- `originality_score`
- `penalty_score`
- `final_score`
- machine-readable explanation/breakdown

## Candidate

Editorial candidate generated by deterministic policy.

Fields:

- `repository_id`
- `score_id`
- `reason`
- `status`
- `created_at`
- `expires_at` optional
- `dedupe_key`

Candidate status examples:

- `CANDIDATE`
- `ANALYSIS_PENDING`
- `REVIEW`
- `WATCHING`
- `REJECTED`
- `APPROVED`
- `EXPIRED`

## Analysis

Bounded LLM output.

Fields:

- `candidate_id`
- `analysis_version`
- `prompt_version`
- `provider`
- `model`
- validated structured output
- `created_at`
- `status`
- bounded token/cost metadata

Do not treat analysis as authorization.

## EditorialDecision

Trusted human decision.

Fields:

- `candidate_id`
- `editor_actor_id`
- `decision` (`APPROVE`, `WATCH`, `REJECT`)
- `decided_at`
- optional note

## Publication

Desired publication intent.

Fields:

- `candidate_id`
- `editorial_decision_id`
- `channel`
- `content_version`
- `idempotency_key`
- `status`
- `created_at`

Unique: `idempotency_key`.

## PublicationAttempt

Provider delivery attempt.

Fields:

- `publication_id`
- `attempt_number`
- `started_at`
- `finished_at`
- provider message/post ID when successful
- normalized error code/status

Never store provider tokens.

## Future analytics/OUTSCAN attribution

Later entities may include:

- campaign
- content attribution
- click/referral event
- OUTSCAN campaign reference

These must not feed VIBE SCORE.
