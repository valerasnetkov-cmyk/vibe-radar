## Security Review

- External GitHub/source text and AI output remain untrusted data.
- AI output cannot publish, execute tools, access shell, or authorize editorial actions.
- Editor callbacks require strict parsing and configured identity authorization.
- Publication requires approved candidate state and a unique idempotency key.
- OUTSCAN flags remain closed by default and are not score/ranking inputs.
- No real credentials were added.

## Blockers

- PostgreSQL integration was not executed because Docker and `DATABASE_URL` are unavailable in the environment.
- Live GitHub/Telegram/AI provider calls were not executed by policy; provider boundaries use mocks/unit tests.
- Worker schedules remain unconfigured and therefore no discovery or scoring jobs are auto-started.
- Real channel view/click events are not generated locally; analytics remains an ingestion boundary until provider event sources are connected.
- Public mechanic cards remain deferred; proposals require source traceability and editor review before public exposure.
- Opportunity text remains analysis and is not treated as source evidence; public cards render only records that pass publication status checks.
- Public mechanic/opportunity surfaces now exist, but render no records until their database status and editorial thresholds are satisfied.
- Collection remains disabled unless `GITHUB_DISCOVERY_QUERIES` is explicitly configured; score scheduling has no effect until snapshots exist.
- Telegram webhook remains unavailable until `TELEGRAM_WEBHOOK_SECRET` and editor IDs are configured; the route cannot publish directly.
